# 上海 / 北京实盘 AWC：2026-10-25、26 无损精简包

## 用途与范围

这是实盘天气日志的离线回放输入，不是新下载的历史天气，也不是独立 47 站采集器的数据。
北京时间窗口 `[2026-10-25 00:00:00, 2026-10-27 00:00:00)`，上海 ZSPD / 北京 ZBAA。
不含 L2、交易凭据、完整策略配置或订单/账户快照；不访问任何网络、Redis 或业务服务。

原记录的 309819 个 METAR 条目中只有 312 种不同的完整 JSON 内容。
本包只对完全相同的 JSON 内容去重，以 ID 引用代替反复保存的观测内容。
**不是只保留最高温，也没有把同一 obsTime 的不同更正合并。**

以下信息均保留：每次响应的完整观测列表及顺序、接收时间、Event/run、来源追溯字段、
投递/错误/退出记录，以及原 JSON 数值的精确文本。
两日合计 6568 条原导出记录，逐字节还原后与原两份 JSONL 的 SHA256 完全一致。

## 直接使用：Python 3.10+，无需第三方依赖

解压后进入本目录，校验：

```sh
python replay_awc.py --verify
```

### 推荐：直接流式读取，不展开大文件

```python
from replay_awc import iter_events

for day in ("2026-10-25", "2026-10-26"):
    for event in iter_events(day):
        if event["kind"] != "metar_poll":
            continue  # 投递、错误、退出不是第二份正常天气响应
        received_ns = event["record"]["received_ns"]  # Python int，不要转 float
        rows = event["record"]["rows"]
        event_id = event["event_id"]
        run_id = event["run_id"]
        # 在 >= received_ns 且符合实际投递/处理模型的时刻使用这份完整响应。
        # 然后复用对应实盘版本的归一化/策略规则，与当时可得的 L2 对齐。
```

`iter_events` 返回原导出格式：外层为来源和时间信息，`record` 是原始日志对象。
JSON 小数解析为 Decimal，整数保持 int。它不是策略引擎，也不会提交订单。

### 如果现有工具必须读两份普通 JSONL

```sh
python replay_awc.py --restore ./restored
```

会先校验，再创建两份原 JSONL，拒绝覆盖已有同名文件。
注意：还原需要约 132 MiB，因为还原会重新展开重复内容；传输和直接流式读取不需要展开。

## 文件

- `observations.jsonl`：312 个精确 JSON 内容片段，`id` 从 0 连续编号，`json` 是原 JSON 文本字符串。
- `events-2026-10-25.jsonl`、`events-2026-10-26.jsonl`：每次原记录的接收时间、Event、站点等索引。
  天气响应通过 `row_ids` 引用观测；`prefix`、`suffix`、分隔符用于逐字节还原，
  其他记录通过 `literal` 保留。建议使用随包 reader，不必手工拼接。
- `replay_awc.py`：可移植标准库 reader / 校验 / 可选还原工具，不含本机绝对输入路径。
- `manifest.json`：格式、计数、成员哈希及原 JSONL 哈希。
- `coverage.json`：原始来源清单和逐日/站点/Event 覆盖及缺口统计，绝对路径只是追溯元数据。
- `validation.json`：两日原文件逐字节还原哈希验证结果。
- `SHA256SUMS`：本目录其余成员的 SHA256。

Linux 可用 `sha256sum -c SHA256SUMS`，macOS 可用 `shasum -a 256 -c SHA256SUMS`。

| 日期 | 站点 | 非空响应 | 错误记录 | 首次—末次非空响应（北京时间） | 同站最长相邻非空响应间隔 |

| 10/25 | ZBAA 北京 | 247 | 2 | 19:44:26—23:59:57 | 141.472 秒 |

- 10/25 所查实盘天气日志没有 19:44 前的响应，不能称全天覆盖。
- 10/26 近全天有响应但存在错误和间隔，不能称全天无故障。
- 非空响应不等于归一化成功、策略已处理或应该成交；没有运行成交回测。
- 间隔不含日初/日末未覆盖时长；单站缺口看 `coverage.json` 的 `stations` / `events`，
  不要使用混合两站的 `all_weather_records` 间隔当作单站间隔。

## 回放必须遵守

1. 以本机 `received_ns` 作为最早可得时间，不能按历史 `obsTime` / AWC `receiptTime` 提前注入。
   原响应里包含历史窗口内的老观测，不代表实盘在老观测时刻已经知道它们。
2. 按 `run_id` / `event_id` 保持原生命周期；不自行跨重启续接状态，不去掉重复轮询，不补缺口。
3. `metar_delivered` 是投递记录，不是第二份响应或策略处理完成回执。
   严格触发时间核对还需要原审计里的 `processed_ns`、对应版本/配置及状态。
4. `metar_error` 可能使用请求前的 `received_ns`，原 `recorded_at_ns` 也保留；
   不能把错误时间当成真实响应完成时间，不能当正常天气注入。
5. L2 应使用可比较的本机接收时间；只有交易所时间时必须承认延迟/时钟差的不确定性。
   决策只使用当时已可得的盘口，不能读取未来快照。
6. 纳秒用精确整数，温度/价格/数量用 Decimal 或相应域类型，不经双精度浮点中转。
7. 本包证明提取和无损打包完整性，不证明历史全天健康，也不单独证明实盘应成交或不成交。
