## 不重复累计的扫单情景

另给两种简单的“首次机会”估计，不伪装成真实成交或完整 Nautilus 执行回测：

- 每个 condition 首次满足条件且累计合格卖盘达到最小数量时，一次扫掉全部合格深度，
  此后不再重复计算该 condition。共 11 个 condition，投入 **5,636.2023384965**，
  条件净利润 **10.9776615035**。它可能错过后续新增的容量，并非全天可扫量上限。
- 按当前实盘每单/condition 上限 5 份、每 Event 尝试预算 100 pUSD，
  在最佳卖价可满足最小数量的首次机会假设立即成交；不模拟 maker 挂单。
  共 11 笔、55 份，投入 **54.887989**，条件净利润 **0.112011**。

第二种采用实盘最佳卖价、份数与尝试成本公式，但没有模拟已有持仓、未成交订单、
撮合竞争、延迟、失败重试或账户恢复，所以它是额度约束下的条件估计，不能叫实盘战绩。
这 11 个产生机会的 condition 都在 10/20～23，保存数据没有实际结算证据，
**实际结算收益未知**。10/16、19 有结算证据但本次覆盖内没有对应假设买入。

## 时间、费用与数据边界

- 使用已记录的 Event 天气模式：10/16～22 为 decoded-temperature，10/23 为
  awc-routine-rounded-celsius-v1；后者复用当前主目录冻结的 METAR 解析函数。
- 天气按本机 received_ns 生效，上游 receiptTime 只用于同观测更正去重；不把后来
  收到的天气提前使用。轮询信号 120 秒过期，观测最多 4500 秒；错误撤销信号。
  同一 received_ns 的 poll→normalize error 原始记录均保留，但计算时原子地按 error 处理。
- 容量使用已初始化的原生 L2 盘口与全深度 NO asks，不叠加镜像 YES bids。
  价格不超过 0.999；每单位边际为 `1-p-rate*p*(1-p)-0.00001-margin`，
  满足 minimum_edge，并检查最小交易数量。没有凭空补买盘或深度。
- 当前实盘代码的容量分支没有执行 `max_book_age_ns` 检查，本统计不额外加入
  五秒盘口过期政策。Catalog 的计划到期时间不当作实际关闭或裁掉更晚行情。
  没有历史 accepting_orders/断线状态的完全复现，容量仍是条件可见深度估计。
- 费率来自保存的该 Event 业务配置：10/16～21 使用 0.05 的 `p*(1-p)` 曲线，
  10/22～23 明确为 0。这是配置情景，未独立验证历史实际手续费，也不含返佣、奖励。
- 17/18 无 AWC；各日未覆盖的午夜和天气失效时间不被当作零机会。
  23 日有较晚天气日志，但严格限制在冻结盘口截止时刻，不凭天气延长盘口覆盖。
